3.1 O pacote tidyverse

O que é e por que usar

Para trabalhar com leitura e manipulação de dados, você deverá instalar um pacote do R chamado tidyverse.

O tidyverse é uma coleção de oito pacotes R desenvolvidos para operar de forma integrada, compartilhando uma mesma filosofia de design, gramática e estrutura de dados. Juntos, eles cobrem todo o fluxo típico de análise de dados — da importação à comunicação dos resultados.

Os principais pacotes que compõem o tidyverse e suas funções são:

Pacote Função principal
readr Importação de arquivos tabulares (.csv, .tsv, .txt)
readxl Importação de arquivos Excel (.xls, .xlsx)
dplyr Transformação e resumo de dados tabulares
tidyr Organização e reestruturação de dados
ggplot2 Criação de gráficos e visualizações
stringr Manipulação de texto e strings
forcats Manipulação de variáveis categóricas (fatores)
purrr Programação funcional e iteração

Por que usar o tidyverse? Além de facilitar a leitura e escrita do código, os pacotes do tidyverse foram projetados para trabalhar com dados organizados (tidy data): cada variável em uma coluna, cada observação em uma linha e cada valor em uma célula. Esse padrão torna a análise mais intuitiva e reprodutível.

Instalação e carregamento

A instalação do tidyverse precisa ser feita apenas uma vez por máquina. Já o carregamento com library() deve ser feito toda vez que iniciar uma nova sessão no R.

3.3 Importando dados

Antes de analisar qualquer conjunto de dados, precisamos carregá-lo no ambiente do R. Existem diferentes formas de fazer isso dependendo do formato do arquivo. Nesta seção, abordaremos os dois tipos mais comuns: arquivos tabulares e arquivos Excel.

Arquivos tabulares: read.table(), read_csv(), read_csv2() e read_tsv()

Arquivos tabulares organizam os dados em linhas e colunas, separadas por um caractere delimitador específico. Os formatos mais comuns são:

  • .csv — colunas separadas por vírgula (,) ou ponto e vírgula (;)
  • .tsv — colunas separadas por tabulação (\t)
  • .txt — colunas separadas por espaço ou outro delimitador customizado

Para importar esses arquivos, podemos usar funções nativas do R ou funções do pacote readr, parte do ecossistema tidyverse. A principal vantagem do readr é a maior velocidade de leitura e a inferência automática mais precisa dos tipos de cada coluna.

Função Delimitador Pacote
read.table("file.txt") Espaço Base R
read_csv("file.csv") Vírgula (,) readr
read_csv2("file.csv") Ponto e vírgula (;) readr
read_tsv("file.tsv") Tabulação (\t) readr

Atenção: arquivos .csv brasileiros frequentemente usam ponto e vírgula como separador (pois a vírgula é o separador decimal no Brasil). Nesses casos, use read_csv2() em vez de read_csv().

As funções do readr também permitem configurar o comportamento da importação por meio de argumentos adicionais. Os mais utilizados são:

dados <- read_csv(
  "file.csv",
  col_names = TRUE,        # indica se a primeira linha contém o nome das colunas
  skip = 2,                # ignora as 2 primeiras linhas antes de começar a leitura
  n_max = 100,             # importa no máximo 100 linhas
  na = c("", "NA", "N/A")  # define quais valores serão tratados como NA
)

Arquivos Excel: read_excel()

Arquivos Excel (.xls e .xlsx) são amplamente utilizados em ambientes corporativos e acadêmicos. Para importá-los no R, utilizamos o pacote readxl, também parte do tidyverse.

library(readxl)

# Importando um arquivo Excel
dados <- read_excel("file.xlsx")

A função read_excel() identifica automaticamente a extensão do arquivo, funcionando tanto para .xls quanto para .xlsx.

Arquivos Excel muitas vezes contêm múltiplas abas e linhas de cabeçalho formatadas. Os argumentos abaixo ajudam a lidar com essas situações:

# Verificar o nome das abas do arquivo Excel antes de importar
excel_sheets("file.xlsx")

dados <- read_excel(
  "file.xlsx",
  sheet = "Plan1",    # nome ou índice da aba a ser importada (padrão: primeira aba)
  skip = 3,           # ignora as 3 primeiras linhas (útil quando há cabeçalhos formatados)
  n_max = 200,        # importa no máximo 200 linhas
  na = c("", "NA")    # define quais valores serão tratados como NA
)

3.4 O operador pipe (%>% e |>)

O pipe é um operador que encadeia funções de forma sequencial, tornando o código mais legível e organizado. Em vez de aninhar funções dentro de outras ou criar objetos intermediários desnecessários, o pipe passa o resultado de uma expressão diretamente como primeiro argumento da próxima.

Pipe sem e com %>%: comparação

Veja o mesmo código escrito de duas formas:

# Sem pipe: funções aninhadas, leitura de dentro para fora
glimpse(filter(select(surto, id, caso, sexo), caso == 1))

# Com pipe: leitura sequencial, de cima para baixo
surto %>%
  select(id, caso, sexo) %>%
  filter(caso == 1) %>%
  glimpse()

A versão com pipe é muito mais fácil de ler e modificar — cada linha representa um passo claro da transformação.

Dois tipos de pipe

A saída do glimpse() apresenta as seguintes informações:

  • Rows: número de linhas do banco, ou seja, o total de observações (indivíduos, registros).

Tipos de variáveis no R

Ao inspecionar o banco, você notará que cada variável possui uma sigla que indica seu tipo. Compreender esses tipos é fundamental, pois o R aplica operações diferentes dependendo da classificação da variável. Os principais tipos são:

No banco surto, encontramos três tipos presentes:

  • dbl (double): variáveis numéricas quantitativas, como leuco, hb e tgl.
  • dttm (datetime): variáveis de data e hora, como dtisint e horaisint.
  • chr (character): variáveis de texto, como ocupa.

Atenção: é comum que variáveis categóricas como sexo, caso ou gravidade sejam importadas como dbl ou chr, quando na verdade deveriam ser tratadas como fatores (fct). Isso ocorre porque o R não consegue inferir automaticamente o significado dos valores — essa correção deve ser feita pelo analista antes de iniciar a análise.

Identificando dados faltantes (NA)

Dados faltantes são representados no R pelo valor NA (Not Available). Eles aparecem quando uma informação não foi coletada, não foi registrada ou foi perdida durante o processo de importação. Ignorar a presença de NA pode comprometer os resultados da análise.

Uma forma rápida de verificar a presença de dados faltantes em todo o banco é usar a combinação das funções is.na() e colSums():

3.6 Transformando variáveis: mutate()

Após inspecionar o banco de dados com glimpse(), identificamos variáveis que estão classificadas como numéricas (dbl) mas que, na prática, representam categorias — como sexo, presença de sintomas ou gravidade do caso. Antes de iniciar qualquer análise, precisamos corrigir essas classificações para que o R as interprete corretamente.

A função mutate() do pacote dplyr é o principal verbo para criar ou modificar variáveis dentro de um banco de dados. Ela pode ser usada tanto para converter tipos quanto para calcular novas colunas a partir das existentes.

Convertendo numéricas em categóricas com factor()

Combinada com factor(), a função mutate() converte variáveis numéricas em categóricas, atribuindo rótulos legíveis aos seus níveis.

A estrutura básica é:

banco_modificado <- banco %>%
  mutate(variavel = factor(variavel, labels = c("Categoria 1", "Categoria 2")))
  • labels: define os rótulos que substituirão os valores numéricos (ex: 0 vira "Não", 1 vira "Sim").
  • order = TRUE: usado quando a variável é ordinal, ou seja, quando existe uma ordem entre os níveis (ex: "Leve" < "Moderado" < "Grave").

Atenção: a ordem dos labels deve sempre corresponder à ordem crescente dos valores numéricos originais. Se no banco o valor 0 representa "Não" e 1 representa "Sim", os labels devem ser c("Não", "Sim") — nessa ordem.

Aplicando ao banco surto:

Criando novas variáveis com mutate()

Além de converter tipos, o mutate() é frequentemente usado para criar novas variáveis a partir das existentes. Dois recursos muito úteis para isso são operações aritméticas simples e a função case_when().

Exemplo 1: calcular a idade a partir da data de nascimento:

library(lubridate)

surto_modif <- surto_modif %>%
  mutate(idade = as.numeric(difftime(dtisint, dtnasc, units = "days")) / 365.25)

Exemplo 2: categorizar uma variável numérica com case_when(). Suponha que queiramos classificar os participantes em faixas etárias:

surto_modif <- surto_modif %>%
  mutate(faixa_etaria = case_when(
    idade < 30              ~ "Menos de 30 anos",
    idade >= 30 & idade < 50 ~ "30 a 49 anos",
    idade >= 50             ~ "50 anos ou mais"
  ))

A função case_when() avalia as condições em ordem e atribui o valor correspondente à primeira condição verdadeira. É o equivalente do if/else aplicado a vetores inteiros.

3.8 Filtrando observações: filter()

Enquanto o select() trabalha com colunas, o filter() trabalha com linhas: ele mantém apenas as observações que atendem a uma condição lógica especificada.

A estrutura básica é:

banco_filtrado <- banco %>%
  filter(condição)

3.10 Resumindo dados: summarise()

A função summarise() (ou summarize()) condensa o banco de dados em uma tabela de resumo, aplicando funções de agregação a uma ou mais variáveis. Ela é especialmente poderosa quando combinada com group_by().

Funções de agregação

As funções mais comuns utilizadas dentro do summarise() são:

Função O que calcula
n() Número de observações
mean(x, na.rm = TRUE) Média
sd(x, na.rm = TRUE) Desvio padrão
var(x, na.rm = TRUE) Variância
median(x, na.rm = TRUE) Mediana
min(x, na.rm = TRUE) Valor mínimo
max(x, na.rm = TRUE) Valor máximo
sum(x, na.rm = TRUE) Soma

Sobre o argumento na.rm = TRUE: por padrão, se houver qualquer NA na variável, o resultado será NA. O argumento na.rm = TRUE instrui o R a ignorar os valores faltantes no cálculo.

# Resumindo a variável leuco com diversas medidas
surto_modif %>% 
  summarise(
    media = mean(leuco, na.rm = TRUE),
    dp    = sd(leuco, na.rm = TRUE),
    min   = min(leuco, na.rm = TRUE),
    max   = max(leuco, na.rm = TRUE),
    n     = n()
  )
# A tibble: 1 × 5
  media    dp   min   max     n
  <dbl> <dbl> <dbl> <dbl> <int>
1 8714. 3700.   698 18557   150

Resumindo múltiplas variáveis com across()

Assim como no mutate(), podemos combinar summarise() com across() para aplicar a mesma função a várias colunas de uma só vez:

# Calculando a média de todas as variáveis laboratoriais de uma vez
surto_modif %>%
  summarise(across(c(leuco, hb, tgl), ~ mean(.x, na.rm = TRUE)))

Isso evita repetição de código quando o número de variáveis é grande, e funciona com qualquer função de agregação.

Resumindo por grupo com group_by()

O group_by() divide o banco em grupos com base nos valores de uma variável. Sozinho, ele não altera a aparência dos dados — a mudança ocorre quando combinado com outros verbos do dplyr, como o summarise().

# Média de leucócitos por status de caso (doente vs. não doente)
surto_modif %>% 
  group_by(caso) %>% 
  summarise(media_leuco = mean(leuco, na.rm = TRUE))
# A tibble: 2 × 2
  caso  media_leuco
  <fct>       <dbl>
1 Não         6385.
2 Sim        13373.
# Frequência absoluta por status de caso
surto_modif %>% 
  group_by(caso) %>% 
  summarise(frequencia = n())
# A tibble: 2 × 2
  caso  frequencia
  <fct>      <int>
1 Não          100
2 Sim           50

Também podemos agrupar por mais de uma variável ao mesmo tempo:

# Média de leucócitos por caso e sexo
surto_modif %>% 
  group_by(caso, sexo) %>% 
  summarise(media_leuco = mean(leuco, na.rm = TRUE),
            n = n())

Boa prática: após usar group_by(), é recomendável usar ungroup() ao final para remover o agrupamento e evitar comportamentos inesperados em operações subsequentes:

surto_modif %>%
  group_by(caso) %>%
  summarise(media = mean(leuco, na.rm = TRUE)) %>%
  ungroup()

3.11 Unindo tabelas: left_join(), right_join(), full_join() e inner_join()

Em análises de saúde, é comum trabalhar com múltiplas tabelas que precisam ser combinadas — por exemplo, uma tabela com dados clínicos e outra com dados laboratoriais, ligadas por um identificador comum como o id do paciente. As funções *_join() do dplyr realizam essa união com base em uma ou mais colunas em comum, chamadas de chaves.

Preparando os dados de exemplo

Para ilustrar as funções, criaremos dois subconjuntos do banco surto:

  select(id, caso, sexo) %>% 
  filter(id %in% c(2, 4, 5, 6))

# df2: indivíduos 2, 3, 4 e 5 com variáveis id e ocupa
df2 <- surto_modif %>% 
  select(id, ocupa) %>% 
  filter(id %in% c(2, 3, 4, 5))

3.12 Exportando dados: write_csv() e write_xlsx()

Após manipular e transformar o banco de dados, é importante salvar o resultado para uso futuro ou compartilhamento. Para isso, utilizamos funções de exportação.

Exportando para .csv

O pacote readr oferece as funções write_csv() e write_csv2() para salvar data frames em formato .csv:

library(readr)

# Exportando com vírgula como separador (padrão internacional)
write_csv(surto_modif, "surto_modificado.csv")

# Exportando com ponto e vírgula (padrão brasileiro — compatível com Excel em PT-BR)
write_csv2(surto_modif, "surto_modificado.csv")

Qual usar? Se o arquivo será aberto no Excel configurado em português do Brasil, prefira write_csv2(), pois o Excel brasileiro usa ponto e vírgula como separador e vírgula como decimal.

Exportando para .xlsx

Para exportar em formato Excel, utilizamos o pacote writexl:

# Instalar o pacote (apenas uma vez)
install.packages("writexl")

library(writexl)

# Exportando para Excel
write_xlsx(surto_modif, "surto_modificado.xlsx")

Para exportar múltiplas tabelas em abas diferentes do mesmo arquivo Excel:

write_xlsx(
  list("Dados completos" = surto_modif,
       "Sintomas"        = surto2,
       "Resumo"          = surto_modif %>% group_by(caso) %>% summarise(n = n())),
  "surto_relatorio.xlsx"
)

Definindo o caminho de saída

Por padrão, os arquivos são salvos no diretório de trabalho atual. Para verificar ou alterar o diretório:

# Verificar o diretório atual
getwd()

# Alterar o diretório de trabalho
setwd("C:/Users/seu_usuario/Documents/projeto")

# Ou especificar o caminho completo diretamente na função
write_csv(surto_modif, "C:/Users/seu_usuario/Documents/projeto/surto_modificado.csv")

Boas práticas: em projetos no RStudio, prefira usar R Projects (.Rproj) em vez de setwd(). Com um projeto aberto, o diretório de trabalho já aponta automaticamente para a pasta do projeto, tornando os caminhos relativos e o código reprodutível em qualquer máquina.

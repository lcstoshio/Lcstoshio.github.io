1  Manipulação de Dados em Saúde

Você sabe como Ler e Manipular Dados?

Ler e manipular dados pode não ser tarefa fácil, mas neste capítulo vamos simplificar tudo para que você possa entender melhor! Ao longo desta seção, você aprenderá a carregar bases de dados no R, inspecionar sua estrutura e aplicar as principais transformações usadas na prática em saúde.

1.1 O pacote tidyverse

1.1.1 O que é e por que usar

Para trabalhar com leitura e manipulação de dados, você deverá instalar um pacote do R chamado tidyverse.

O tidyverse é uma coleção de pacotes R desenvolvidos para operar de forma integrada, compartilhando uma mesma filosofia de design, gramática e estrutura de dados. Juntos, eles cobrem todo o fluxo típico de análise de dados — da importação à comunicação dos resultados.

Os principais pacotes que compõem o tidyverse e suas funções são:

Pacote Função principal
readr Importação de arquivos tabulares, como .csv, .tsv e .txt
dplyr Manipulação, transformação e resumo de dados tabulares
tidyr Organização e reestruturação de dados em formato tidy
ggplot2 Criação de gráficos e visualizações
tibble Criação e manipulação de tabelas modernas do tidyverse
stringr Manipulação de texto e strings

purrr Programação funcional, iteração e aplicação de funções em listas
lubridate Manipulação, conversão e extração de informações de datas e horários
Por que usar o tidyverse?

Além de facilitar a leitura e escrita do código, os pacotes do tidyverse foram projetados para trabalhar com dados organizados (tidy data): cada variável em uma coluna, cada observação em uma linha e cada valor em uma célula. Esse padrão torna a análise mais intuitiva e reprodutível.

1.1.2 Instalação e carregamento

A instalação do tidyverse precisa ser feita apenas uma vez por máquina. Já o carregamento com library() deve ser feito toda vez que iniciar uma nova sessão no R.

install.packages("tidyverse") # Instala o pacote tidyverse (executar apenas uma vez)

1.3 Importando dados

Antes de analisar qualquer conjunto de dados, precisamos carregá-lo no ambiente do R. Existem diferentes formas de fazer isso dependendo do formato do arquivo. Nesta seção, abordaremos os dois tipos mais comuns: arquivos tabulares e arquivos Excel.

1.3.1 Arquivos tabulares: read.table(), read_csv(), read_csv2() e read_tsv()

Arquivos tabulares organizam os dados em linhas e colunas, separadas por um caractere delimitador específico. Os formatos mais comuns são:

  • .csv — colunas separadas por vírgula (,) ou ponto e vírgula (;)
  • .tsv — colunas separadas por tabulação (\t)
  • .txt — colunas separadas por espaço ou outro delimitador customizado

Para importar esses arquivos, podemos usar funções nativas do R ou funções do pacote readr, parte do ecossistema tidyverse. A principal vantagem do readr é a maior velocidade de leitura e a inferência automática mais precisa dos tipos de cada coluna.

Função Delimitador Pacote
read.table("file.txt") Espaço Base R
read_csv("file.csv") Vírgula (,) readr
read_csv2("file.csv") Ponto e vírgula (;) readr
read_tsv("file.tsv") Tabulação (\t) readr
Atenção

Arquivos .csv brasileiros frequentemente usam ponto e vírgula como separador (pois a vírgula é o separador decimal no Brasil). Nesses casos, use read_csv2() em vez de read_csv().

As funções do readr também permitem configurar o comportamento da importação por meio de argumentos adicionais. Os mais utilizados são:

dados <- read_csv(
  "./file.csv",            # caminho e nome do arquivo
  col_names = TRUE,        # indica se a primeira linha contém o nome das colunas
  skip = 2,                # ignora as 2 primeiras linhas antes de começar a leitura
  n_max = 100,             # importa no máximo 100 linhas
  na = c("", "NA", "N/A")  # define quais valores serão tratados como NA
)

1.3.2 Arquivos Excel: read_excel()

Arquivos Excel (.xls e .xlsx) são amplamente utilizados em ambientes corporativos e acadêmicos. Para importá-los no R, utilizamos o pacote readxl, também parte do tidyverse.

library(readxl)

# Importando um arquivo Excel
dados <- read_excel("file.xlsx")

A função read_excel() identifica automaticamente a extensão do arquivo, funcionando tanto para .xls quanto para .xlsx.

Arquivos Excel muitas vezes contêm múltiplas abas e linhas de cabeçalho formatadas. Os argumentos abaixo ajudam a lidar com essas situações:

# Verificar o nome das abas do arquivo Excel antes de importar
excel_sheets("file.xlsx")

dados <- read_excel(
  "./file.xlsx",      # caminho e nome do arquivo
  sheet = "Plan1",    # nome ou índice da aba a ser importada (padrão: primeira aba)
  skip = 3,           # ignora as 3 primeiras linhas (útil quando há cabeçalhos formatados)
  n_max = 200,        # importa no máximo 200 linhas
  na = c("", "NA")    # define quais valores serão tratados como NA
)

1.4 O operador pipe (%>% e |>)

O pipe é um operador que encadeia funções de forma sequencial, tornando o código mais legível e organizado. Em vez de aninhar funções dentro de outras ou criar objetos intermediários desnecessários, o pipe passa o resultado de uma expressão diretamente como primeiro argumento da próxima.

1.4.1 Pipe sem e com %>%: comparação

Veja o mesmo código escrito de duas formas:

# Sem pipe: funções aninhadas, leitura de dentro para fora
glimpse(filter(select(surto, id, caso, sexo), caso == 1))

# Com pipe: leitura sequencial, de cima para baixo
surto %>%
  select(id, caso, sexo) %>%
  filter(caso == 1) %>%
  glimpse()

A versão com pipe é muito mais fácil de ler e modificar — cada linha representa um passo claro da transformação.

1.4.2 Dois tipos de pipe

Atualmente existem dois pipes disponíveis no R:

Pipe Origem Disponibilidade
%>% Pacote magrittr / tidyverse Qualquer versão do R com o pacote carregado
\|> Base R (nativo) R 4.1.0 ou superior

Para a maioria dos usos, os dois se comportam de forma idêntica. Neste livro, utilizaremos o %>% por ser o mais comumente utilizado no tidyverse. No RStudio, o atalho Ctrl + Shift + M insere o pipe automaticamente.

A partir daqui, usaremos o pipe em todas as análises para encadear as funções do dplyr.

Ao inspecionar o banco, você notará que cada variável possui uma sigla que indica seu tipo. Compreender esses tipos é fundamental, pois o R aplica operações diferentes dependendo da classificação da variável. Os principais tipos são:

  • dbl (double): variáveis numéricas quantitativas, como leuco, hb e tgl.

1.6 Transformando variáveis: mutate()

Após inspecionar o banco de dados com glimpse(), identificamos variáveis que estão classificadas como numéricas (dbl) mas que, na prática, representam categorias — como sexo, presença de sintomas ou gravidade do caso. Antes de iniciar qualquer análise, precisamos corrigir essas classificações para que o R as interprete corretamente.

A função mutate() do pacote dplyr é o principal verbo para criar ou modificar variáveis dentro de um banco de dados. Ela pode ser usada tanto para converter tipos quanto para calcular novas colunas a partir das existentes.

1.6.1 Convertendo numéricas em categóricas com factor()

Combinada com factor(), a função mutate() converte variáveis numéricas em categóricas, atribuindo rótulos legíveis aos seus níveis.

A estrutura básica é:

banco_modificado <- banco %>%
  mutate(variavel = factor(variavel, labels = c("Categoria 1", "Categoria 2")))
  • labels: define os rótulos que substituirão os valores numéricos (ex: 0 vira "Não", 1 vira "Sim").
  • order = TRUE: usado quando a variável é ordinal, ou seja, quando existe uma ordem entre os níveis (ex: "Leve" < "Moderado" < "Grave").
Atenção

1.6.2 Criando novas variáveis com mutate()

Além de converter tipos, o mutate() é frequentemente usado para criar novas variáveis a partir das existentes. Dois recursos muito úteis para isso são operações aritméticas simples e a função case_when().

Exemplo 1: calcular a idade a partir da data de nascimento:

library(lubridate)

surto_modif <- surto_modif %>%
  mutate(idade = as.numeric(difftime(dtisint, dtnasc, units = "days")) / 365.25)

Exemplo 2: categorizar uma variável numérica com case_when(). Suponha que queiramos classificar os participantes em faixas etárias:

surto_modif <- surto_modif %>%
  mutate(faixa_etaria = case_when(
    idade < 30              ~ "Menos de 30 anos",
    idade >= 30 & idade < 50 ~ "30 a 49 anos",
    idade >= 50             ~ "50 anos ou mais"
  ))

A função case_when() avalia as condições em ordem e atribui o valor correspondente à primeira condição verdadeira. É o equivalente do if/else aplicado a vetores inteiros.

1.6.3 Automatizando com across()

Quando queremos aplicar a mesma transformação a várias colunas ao mesmo tempo, podemos usar a função across() dentro do próprio mutate(). Essa é a abordagem moderna e recomendada pelo dplyr.

1.7.3 Funções auxiliares do tidyselect

O select() também aceita funções auxiliares que tornam a seleção mais flexível, sem precisar listar cada coluna manualmente:

Função O que faz
starts_with("x") Seleciona colunas cujo nome começa com "x"
ends_with("x") Seleciona colunas cujo nome termina com "x"

1.8 Filtrando observações: filter()

Enquanto o select() trabalha com colunas, o filter() trabalha com linhas: ele mantém apenas as observações que atendem a uma condição lógica especificada.

A estrutura básica é:

banco_filtrado <- banco %>%
  filter(condição)

1.10 Resumindo dados: summarise()

A função summarise() (ou summarize()) condensa o banco de dados em uma tabela de resumo, aplicando funções de agregação a uma ou mais variáveis. Ela é especialmente poderosa quando combinada com group_by().

1.10.2 Resumindo múltiplas variáveis com across()

Assim como no mutate(), podemos combinar summarise() com across() para aplicar a mesma função a várias colunas de uma só vez:

# Calculando a média de todas as variáveis laboratoriais de uma vez
surto_modif %>%
  summarise(across(c(leuco, hb, tgl), ~ mean(.x, na.rm = TRUE)))

Isso evita repetição de código quando o número de variáveis é grande, e funciona com qualquer função de agregação.

1.10.3 Resumindo por grupo com group_by()

## Importando dados

Antes de analisar qualquer conjunto de dados, precisamos carregá-lo no ambiente do R. Existem diferentes formas de fazer isso dependendo do formato do arquivo. Nesta seção, abordaremos os dois tipos mais comuns: arquivos tabulares e arquivos Excel.

### Arquivos tabulares: `read.table()`, `read_csv()`, `read_csv2()` e `read_tsv()`

Arquivos tabulares organizam os dados em linhas e colunas, separadas por um caractere delimitador específico. Os formatos mais comuns são:

- **`.csv`** — colunas separadas por vírgula (`,`) ou ponto e vírgula (`;`)
- **`.tsv`** — colunas separadas por tabulação (`\t`)
- **`.txt`** — colunas separadas por espaço ou outro delimitador customizado

Para importar esses arquivos, podemos usar funções nativas do R ou funções do pacote `readr`, parte do ecossistema `tidyverse`. A principal vantagem do `readr` é a maior velocidade de leitura e a inferência automática mais precisa dos tipos de cada coluna.

| Função | Delimitador | Pacote |
|---|---|---|
| `read.table("file.txt")` | Espaço | Base R |
| `read_csv("file.csv")` | Vírgula (`,`) | `readr` |
| `read_csv2("file.csv")` | Ponto e vírgula (`;`) | `readr` |
| `read_tsv("file.tsv")` | Tabulação (`\t`) | `readr` |

::: {.callout-tip}
## Atenção

Arquivos `.csv` brasileiros frequentemente usam ponto e vírgula como separador (pois a vírgula é o separador decimal no Brasil). Nesses casos, use `read_csv2()` em vez de `read_csv()`.
:::

As funções do `readr` também permitem configurar o comportamento da importação por meio de argumentos adicionais. Os mais utilizados são:

```{r}
#| eval: false
dados <- read_csv(
  "./file.csv",            # caminho e nome do arquivo
  col_names = TRUE,        # indica se a primeira linha contém o nome das colunas
  skip = 2,                # ignora as 2 primeiras linhas antes de começar a leitura
  n_max = 100,             # importa no máximo 100 linhas
  na = c("", "NA", "N/A")  # define quais valores serão tratados como NA
)
```

## O operador pipe (`%>%` e `|>`)

O **pipe** é um operador que encadeia funções de forma sequencial, tornando o código mais legível e organizado. Em vez de aninhar funções dentro de outras ou criar objetos intermediários desnecessários, o pipe passa o resultado de uma expressão diretamente como primeiro argumento da próxima.

### Pipe sem e com `%>%`: comparação

Veja o mesmo código escrito de duas formas:

```{r echo=TRUE, eval=FALSE}
# Sem pipe: funções aninhadas, leitura de dentro para fora
glimpse(filter(select(surto, id, caso, sexo), caso == 1))

# Com pipe: leitura sequencial, de cima para baixo
surto %>%
  select(id, caso, sexo) %>%
  filter(caso == 1) %>%
  glimpse()
```

A versão com pipe é muito mais fácil de ler e modificar — cada linha representa um passo claro da transformação.

### Dois tipos de pipe

Atualmente existem dois pipes disponíveis no R:

| Pipe | Origem | Disponibilidade |
|---|---|---|
| `%>%` | Pacote `magrittr` / `tidyverse` | Qualquer versão do R com o pacote carregado |
| `\|>` | Base R (nativo) | R 4.1.0 ou superior |

Para a maioria dos usos, os dois se comportam de forma idêntica. Neste livro, utilizaremos o `%>%` por ser o mais comumente utilizado no `tidyverse`. No RStudio, o atalho `Ctrl + Shift + M` insere o pipe automaticamente.

A partir daqui, usaremos o pipe em todas as análises para encadear as funções do `dplyr`.

## Inspecionando o banco de dados com `glimpse()`

Antes de iniciar qualquer análise, é essencial conhecer bem o banco de dados com o qual estamos trabalhando. Precisamos entender quantas observações e variáveis ele contém, quais são os tipos de cada variável e se existem dados faltantes. Para isso, utilizaremos a função `glimpse()` do pacote `dplyr`.

### Observando as características das variáveis

O comando `glimpse()` oferece um resumo compacto e informativo do banco de dados, exibindo as dimensões, os nomes das variáveis, seus tipos e os primeiros valores de cada coluna — tudo em uma única saída.

```{r echo=TRUE, eval=TRUE}
glimpse(surto)
```

A saída do `glimpse()` apresenta as seguintes informações:

- **Rows:** número de linhas do banco, ou seja, o total de observações (indivíduos, registros).
- **Columns:** número de colunas, ou seja, o total de variáveis disponíveis.
- **Nome da variável:** precedido por `$`, é o identificador da coluna.
- **Tipo da variável:** indicado entre `< >`, logo após o nome (ex: `<dbl>`, `<chr>`).
- **Primeiros valores:** uma prévia dos dados contidos naquela variável.

Como o banco de dados **surto** apresenta 29 colunas e 150 linhas, temos 29 variáveis e 150 indivíduos para explorar.

---

### Tipos de variáveis no R

Ao inspecionar o banco, você notará que cada variável possui uma sigla que indica seu tipo. Compreender esses tipos é fundamental, pois o R aplica operações diferentes dependendo da classificação da variável. Os principais tipos são:

| Tipo | Sigla | Descrição | Exemplo |
|---|---|---|---|
| Double | `dbl` | Número real (com casas decimais) | `1.71`, `68.2` |
| Inteiro | `int` | Número inteiro | `8`, `42` |
| Caractere | `chr` | Texto livre (*string*) | `"masculino"`, `"sim"` |
| Fator | `fct` | Variável categórica com níveis definidos | `"leve"`, `"moderado"`, `"grave"` |
| Lógico | `lgl` | Verdadeiro ou falso | `TRUE`, `FALSE` |
| Data e hora | `dttm` | Data e hora combinadas | `2000-06-08 08:32:00` |
| Data | `date` | Apenas data | `2000-06-08` |

No banco **surto**, encontramos três tipos presentes:

- **`dbl` (double):** variáveis numéricas quantitativas, como `leuco`, `hb` e `tgl`.
- **`dttm` (datetime):** variáveis de data e hora, como `dtisint` e `horaisint`.
- **`chr` (character):** variáveis de texto, como `ocupa`.

::: {.callout-tip}
## Atenção

É comum que variáveis categóricas como `sexo`, `caso` ou `gravidade` sejam importadas como `dbl` ou `chr`, quando na verdade deveriam ser tratadas como **fatores (`fct`)**. Isso ocorre porque o R não consegue inferir automaticamente o significado dos valores — essa correção deve ser feita pelo analista antes de iniciar a análise.
:::

---

### Identificando dados faltantes (`NA`)

Dados faltantes são representados no R pelo valor `NA` (*Not Available*). Eles aparecem quando uma informação não foi coletada, não foi registrada ou foi perdida durante o processo de importação. Ignorar a presença de `NA` pode comprometer os resultados da análise.

Uma forma rápida de verificar a presença de dados faltantes em todo o banco é usar a combinação das funções `is.na()` e `colSums()`:

```{r echo=TRUE, eval=TRUE}
# Conta o número de NA em cada variável
colSums(is.na(surto))
```

Para uma visão mais organizada, podemos transformar o resultado em uma tabela ordenada:

```{r echo=TRUE, eval=TRUE}
# Exibe as variáveis com mais dados faltantes primeiro
surto |>
  summarise(across(everything(), ~ sum(is.na(.)))) |>
  pivot_longer(everything(), names_to = "variavel", values_to = "n_missing") |>
  arrange(desc(n_missing))
```

::: {.callout-tip}
## Boas práticas

Antes de decidir o que fazer com os `NA`, investigue o motivo da ausência. Em dados de saúde, um dado faltante pode significar que o exame não foi realizado, que o paciente recusou responder ou simplesmente que houve falha no preenchimento. Cada situação exige uma abordagem diferente de como tratar esses dados, ou até mesmo a exclusão de linhas inteiras devido à falta de informações essenciais.
:::

## Transformando variáveis: `mutate()`

Após inspecionar o banco de dados com `glimpse()`, identificamos variáveis que estão classificadas como numéricas (`dbl`) mas que, na prática, representam categorias — como sexo, presença de sintomas ou gravidade do caso. Antes de iniciar qualquer análise, precisamos corrigir essas classificações para que o R as interprete corretamente.

A função `mutate()` do pacote `dplyr` é o principal verbo para **criar ou modificar variáveis** dentro de um banco de dados. Ela pode ser usada tanto para converter tipos quanto para calcular novas colunas a partir das existentes.

---

### Convertendo numéricas em categóricas com `factor()`

Combinada com `factor()`, a função `mutate()` converte variáveis numéricas em categóricas, atribuindo rótulos legíveis aos seus níveis.

A estrutura básica é:

```{r echo=TRUE, eval=FALSE}
banco_modificado <- banco %>%
  mutate(variavel = factor(variavel, labels = c("Categoria 1", "Categoria 2")))
```

- **`labels`:** define os rótulos que substituirão os valores numéricos (ex: `0` vira `"Não"`, `1` vira `"Sim"`).
- **`order = TRUE`:** usado quando a variável é ordinal, ou seja, quando existe uma ordem entre os níveis (ex: `"Leve"` < `"Moderado"` < `"Grave"`).

::: {.callout-warning}
## Atenção

A ordem dos `labels` deve sempre corresponder à ordem crescente dos valores numéricos originais. Se no banco o valor `0` representa `"Não"` e `1` representa `"Sim"`, os labels devem ser `c("Não", "Sim")` — nessa ordem.
:::

Aplicando ao banco **surto**:

```{r echo=TRUE, eval=TRUE}
# Transformando variáveis numéricas em categóricas com mutate() e factor()
surto_modif <- surto %>% 
  mutate(
    caso         = factor(caso,         labels = c("Não", "Sim")),
    sexo         = factor(sexo,         labels = c("Feminino", "Masculino")),
    ocupa        = factor(ocupa),
    diarreia     = factor(diarreia,     labels = c("Não", "Sim")),
    colica       = factor(colica,       labels = c("Não", "Sim")),
    vomito       = factor(vomito,       labels = c("Não", "Sim")),
    nausea       = factor(nausea,       labels = c("Não", "Sim")),
    cefaleia     = factor(cefaleia,     labels = c("Não", "Sim")),
    desidratacao = factor(desidratacao, labels = c("Não", "Sim")),
    febre        = factor(febre,        labels = c("Não", "Sim")),
    servsaude    = factor(servsaude,    labels = c("Não", "Sim")),
    gravidade    = factor(gravidade,    labels = c("Leve", "Moderado", "Grave"), order = TRUE),
    salada       = factor(salada,       labels = c("Não", "Sim")),
    pao          = factor(pao,          labels = c("Não", "Sim")),
    medalhao     = factor(medalhao,     labels = c("Não", "Sim")),
    macarrao     = factor(macarrao,     labels = c("Não", "Sim")),
    molhoqueijo  = factor(molhoqueijo,  labels = c("Não", "Sim")),
    molhoverm    = factor(molhoverm,    labels = c("Não", "Sim")),
    pudim        = factor(pudim,        labels = c("Não", "Sim")),
    frutas       = factor(frutas,       labels = c("Não", "Sim")),
    agua         = factor(agua,         labels = c("Não", "Sim")),
    suco         = factor(suco,         labels = c("Não", "Sim"))
  )

# Inspecionando os tipos das variáveis após a transformação
glimpse(surto_modif)
```

Após a transformação, as variáveis que antes apareciam como `<dbl>` devem agora aparecer como `<fct>` no `glimpse()`, e a variável `gravidade` como `<ord>` (fator ordenado).

---

### Criando novas variáveis com `mutate()`

Além de converter tipos, o `mutate()` é frequentemente usado para **criar novas variáveis** a partir das existentes. Dois recursos muito úteis para isso são operações aritméticas simples e a função `case_when()`.

**Exemplo 1:** calcular a idade a partir da data de nascimento:

```{r echo=TRUE, eval=FALSE}
library(lubridate)

surto_modif <- surto_modif %>%
  mutate(idade = as.numeric(difftime(dtisint, dtnasc, units = "days")) / 365.25)
```

**Exemplo 2:** categorizar uma variável numérica com `case_when()`. Suponha que queiramos classificar os participantes em faixas etárias:

```{r echo=TRUE, eval=FALSE}
surto_modif <- surto_modif %>%
  mutate(faixa_etaria = case_when(
    idade < 30              ~ "Menos de 30 anos",
    idade >= 30 & idade < 50 ~ "30 a 49 anos",
    idade >= 50             ~ "50 anos ou mais"
  ))
```

A função `case_when()` avalia as condições em ordem e atribui o valor correspondente à primeira condição verdadeira. É o equivalente do `if/else` aplicado a vetores inteiros.

---

### Automatizando com `across()`

Quando queremos aplicar a mesma transformação a várias colunas ao mesmo tempo, podemos usar a função `across()` dentro do próprio `mutate()`. Essa é a abordagem moderna e recomendada pelo `dplyr`.

Essa abordagem é ideal quando as variáveis não precisam de `labels` personalizados — ou seja, quando basta converter o tipo da coluna sem renomear seus valores.

```{r echo=TRUE, eval=TRUE}
# Convertendo múltiplas variáveis para fator de uma só vez com across()
surto_factor <- surto %>% 
  mutate(across(
    c("caso", "sexo", "ocupa", "diarreia", "colica", "vomito",
      "nausea", "cefaleia", "desidratacao", "febre", "servsaude",
      "gravidade", "salada", "pao", "medalhao", "macarrao",
      "molhoqueijo", "molhoverm", "pudim", "frutas", "agua", "suco"),
    as.factor
  ))

glimpse(surto_factor)
```

A estrutura básica do `across()` é:

```{r echo=TRUE, eval=FALSE}
banco %>%
  mutate(across(c("col1", "col2", "col3"), função))
```

## Selecionando variáveis: `select()`

Nem sempre precisamos trabalhar com todas as variáveis de um banco de dados. A função `select()` do `dplyr` permite escolher apenas as colunas de interesse, tornando o banco mais enxuto e a análise mais organizada.

A estrutura básica é:

```{r echo=TRUE, eval=FALSE}
banco_novo <- banco %>%
  select(variavel1, variavel2, variavel3)
```

---

### Selecionando variáveis por nome

Considere que nosso interesse seja criar uma base de dados (`surto2`) apenas com as variáveis referentes aos sintomas da doença: `id`, `caso`, `sexo`, `dtnasc`, `ocupa`, `dtisint`, `horaisint`, `diarreia`, `colica`, `vomito`, `nausea`, `cefaleia`, `desidratacao`, `febre`, `servsaude` e `gravidade`.

```{r echo=TRUE, eval=TRUE}
# Selecionando colunas pelo nome
surto2 <- surto_modif %>%
  select(id, caso, sexo, dtnasc, ocupa, dtisint, horaisint,
         diarreia, colica, vomito, nausea, cefaleia,
         desidratacao, febre, servsaude, gravidade)

head(surto2)
```

Também podemos fazer o inverso: selecionar todas as colunas **exceto** as que não nos interessam, usando o sinal de menos (`-`):

```{r echo=TRUE, eval=TRUE}
# Excluindo colunas pelo nome
surto3 <- surto_modif %>%
  select(-c(salada, pao, medalhao, macarrao, molhoqueijo,
            molhoverm, pudim, frutas, agua, suco, hb, leuco, tgl))

head(surto3)
```

---

### Selecionando com `all_of()`

Quando as colunas de interesse já estão armazenadas em um vetor de texto, podemos usar `all_of()` dentro do `select()`. Essa função garante que todas as colunas especificadas existam no banco — se alguma estiver ausente, um erro será lançado, evitando seleções silenciosas e incorretas.

```{r echo=TRUE, eval=TRUE}
# Definindo as variáveis de interesse em um vetor
sintomas <- c("id", "diarreia", "colica", "vomito")

# Selecionando com all_of()
surto_ex1 <- surto_modif %>%
  select(all_of(sintomas))

head(surto_ex1)
```

Para excluir essas mesmas variáveis:

```{r echo=TRUE, eval=TRUE}
surto_ex2 <- surto_modif %>% 
  select(-all_of(sintomas))

head(surto_ex2)
```

### Funções auxiliares do `tidyselect`

O `select()` também aceita funções auxiliares que tornam a seleção mais flexível, sem precisar listar cada coluna manualmente:

| Função | O que faz |
|---|---|
| `starts_with("x")` | Seleciona colunas cujo nome começa com `"x"` |
| `ends_with("x")` | Seleciona colunas cujo nome termina com `"x"` |
| `contains("x")` | Seleciona colunas cujo nome contém `"x"` |
| `where(is.numeric)` | Seleciona colunas de um tipo específico |
| `everything()` | Seleciona todas as colunas restantes |

```{r echo=TRUE, eval=FALSE}
# Exemplos de uso
surto_modif %>% select(starts_with("dt"))     # colunas que começam com "dt"
surto_modif %>% select(where(is.numeric))     # apenas colunas numéricas
surto_modif %>% select(id, everything())      # id primeiro, depois o restante
```

## Filtrando observações: `filter()`

Enquanto o `select()` trabalha com **colunas**, o `filter()` trabalha com **linhas**: ele mantém apenas as observações que atendem a uma condição lógica especificada.

A estrutura básica é:

```{r echo=TRUE, eval=FALSE}
banco_filtrado <- banco %>%
  filter(condição)
```

---

### Operadores lógicos e de comparação

Antes de ver os exemplos, é útil conhecer os operadores disponíveis para construir condições no `filter()`:

| Operador | Significado |
|---|---|
| `==` | Igual a |
| `!=` | Diferente de |
| `>`, `<` | Maior que, menor que |
| `>=`, `<=` | Maior ou igual, menor ou igual |
| `&` | E (ambas as condições verdadeiras) |
| `\|` | OU (pelo menos uma condição verdadeira) |
| `!` | NÃO (negação da condição) |
| `%in%` | Pertence a um conjunto de valores |
| `is.na()` | Verifica se o valor é `NA` |

---

### Filtrando por uma condição simples

```{r echo=TRUE, eval=TRUE}
# Filtrando apenas os indivíduos com ocupação "enfermeiro"
surto_enf <- surto_modif %>% 
  filter(ocupa == "enfermeiro")

head(surto_enf)
```

---

### Combinando condições com operadores lógicos

- **OU (`|`):** retorna linhas que satisfazem **pelo menos uma** das condições.

```{r echo=TRUE, eval=TRUE}
# Enfermeiros OU médicos
surto_enf_med <- surto_modif %>% 
  filter(ocupa == "enfermeiro" | ocupa == "medico")

head(surto_enf_med)
```

::: {.callout-tip}
## Dica

Quando há muitas categorias, `%in%` é mais prático que vários `|`:
```r
surto_modif %>% filter(ocupa %in% c("enfermeiro", "medico"))
```
:::

- **E (`&`):** retorna linhas que satisfazem **todas** as condições simultaneamente.

```{r echo=TRUE, eval=TRUE}
# Enfermeiras do sexo feminino
surto_enf_fem <- surto_modif %>% 
  filter(ocupa == "enfermeiro" & sexo == "Feminino")

head(surto_enf_fem)
```

- **Combinando `|` e `&`:** é possível encadear múltiplas condições. A vírgula dentro do `filter()` funciona como um `&`.

```{r echo=TRUE, eval=TRUE}
# Enfermeiros OU médicos, do sexo feminino
surto_enf_med_fem <- surto_modif %>% 
  filter(ocupa == "enfermeiro" | 
         ocupa == "medico" & sexo == "Feminino")

head(surto_enf_med_fem)
```

::: {.callout-tip}
## Atenção com a ordem

Quando combinamos `&` e `|` na mesma expressão, o `&` é avaliado antes do `|`. Use parênteses para deixar a lógica explícita e evitar resultados inesperados:
```r
filter((ocupa == "enfermeiro" | ocupa == "medico") & sexo == "Feminino")
```
:::

- **Filtrando dados faltantes:** para manter ou excluir linhas com `NA` em uma variável:

```{r echo=TRUE, eval=FALSE}
surto_modif %>% filter(is.na(leuco))    # apenas os com NA em leuco
surto_modif %>% filter(!is.na(leuco))   # excluindo os com NA em leuco
```

## Ordenando observações: `arrange()`

A função `arrange()` reordena as linhas do banco de dados com base nos valores de uma ou mais colunas. Por padrão, a ordenação é **crescente**; para ordenação decrescente, usamos `desc()`.

```{r echo=TRUE, eval=TRUE}
# Ordenando de forma crescente pela variável leuco
surto_cresc <- surto_modif %>% 
  arrange(leuco)

head(surto_cresc)
```

```{r echo=TRUE, eval=TRUE}
# Ordenando de forma decrescente
surto_desc <- surto_modif %>% 
  arrange(desc(leuco))

head(surto_desc)
```

Também é possível ordenar por **múltiplas variáveis**. Nesse caso, o R ordena primeiro pela primeira variável e, em caso de empate, pela segunda:

```{r echo=TRUE, eval=FALSE}
# Ordenando por sexo e, dentro de cada sexo, por leuco crescente
surto_modif %>% 
  arrange(sexo, leuco)

# Ordenando por sexo e leuco decrescente
surto_modif %>% 
  arrange(sexo, desc(leuco))
```

No contexto do surto, o `arrange()` é útil para identificar a cronologia dos casos. Por exemplo, ordenar pelo horário de início dos sintomas permite visualizar quem adoeceu primeiro — informação importante para investigar o período de incubação:

```{r echo=TRUE, eval=FALSE}
# Identificando os primeiros casos por horário de início dos sintomas
surto_modif %>%
  filter(caso == "Sim") %>%
  arrange(dtisint, horaisint) %>%
  select(id, dtisint, horaisint, gravidade)
```

::: {.callout-tip}
## Nota sobre `NA`

Valores faltantes (`NA`) são sempre colocados ao final da ordenação, independentemente de ser crescente ou decrescente.
:::

## Resumindo dados: `summarise()`

A função `summarise()` (ou `summarize()`) condensa o banco de dados em uma tabela de resumo, aplicando funções de agregação a uma ou mais variáveis. Ela é especialmente poderosa quando combinada com `group_by()`.

---

### Funções de agregação

As funções mais comuns utilizadas dentro do `summarise()` são:

| Função | O que calcula |
|---|---|
| `n()` | Número de observações |
| `mean(x, na.rm = TRUE)` | Média |
| `sd(x, na.rm = TRUE)` | Desvio padrão |
| `var(x, na.rm = TRUE)` | Variância |
| `median(x, na.rm = TRUE)` | Mediana |
| `min(x, na.rm = TRUE)` | Valor mínimo |
| `max(x, na.rm = TRUE)` | Valor máximo |
| `sum(x, na.rm = TRUE)` | Soma |

::: {.callout-tip}
## `na.rm = TRUE`

Por padrão, se houver qualquer `NA` na variável, o resultado será `NA`. O argumento `na.rm = TRUE` instrui o R a ignorar os valores faltantes no cálculo.
:::

```{r echo=TRUE, eval=TRUE}
# Resumindo a variável leuco com diversas medidas
surto_modif %>% 
  summarise(
    media = mean(leuco, na.rm = TRUE),
    dp    = sd(leuco, na.rm = TRUE),
    min   = min(leuco, na.rm = TRUE),
    max   = max(leuco, na.rm = TRUE),
    n     = n()
  )
```

---

### Resumindo múltiplas variáveis com `across()`

Assim como no `mutate()`, podemos combinar `summarise()` com `across()` para aplicar a mesma função a várias colunas de uma só vez:

```{r echo=TRUE, eval=FALSE}
# Calculando a média de todas as variáveis laboratoriais de uma vez
surto_modif %>%
  summarise(across(c(leuco, hb, tgl), ~ mean(.x, na.rm = TRUE)))
```

Isso evita repetição de código quando o número de variáveis é grande, e funciona com qualquer função de agregação.

---

### Resumindo por grupo com `group_by()`

O `group_by()` divide o banco em grupos com base nos valores de uma variável. Sozinho, ele não altera a aparência dos dados — a mudança ocorre quando combinado com outros verbos do `dplyr`, como o `summarise()`.

```{r echo=TRUE, eval=TRUE}
# Média de leucócitos por status de caso (doente vs. não doente)
surto_modif %>% 
  group_by(caso) %>% 
  summarise(media_leuco = mean(leuco, na.rm = TRUE))
```

```{r echo=TRUE, eval=TRUE}
# Frequência absoluta por status de caso
surto_modif %>% 
  group_by(caso) %>% 
  summarise(frequencia = n())
```

Também podemos agrupar por **mais de uma variável** ao mesmo tempo:

```{r echo=TRUE, eval=FALSE}
# Média de leucócitos por caso e sexo
surto_modif %>% 
  group_by(caso, sexo) %>% 
  summarise(media_leuco = mean(leuco, na.rm = TRUE),
            n = n())
```

## Unindo tabelas: `left_join()`, `right_join()`, `full_join()` e `inner_join()`

Em análises de saúde, é comum trabalhar com múltiplas tabelas que precisam ser combinadas — por exemplo, uma tabela com dados clínicos e outra com dados laboratoriais, ligadas por um identificador comum como o `id` do paciente. As funções `*_join()` do `dplyr` realizam essa união com base em uma ou mais colunas em comum, chamadas de **chaves**.

![Representação das funções "join" do dplyr](./figures/join.jpeg)

---

### Preparando os dados de exemplo

Para ilustrar as funções, criaremos dois subconjuntos do banco **surto**:

```{r echo=TRUE, eval=TRUE}
# df1: indivíduos 2, 4, 5 e 6 com variáveis id, caso e sexo
df1 <- surto_modif %>% 
  select(id, caso, sexo) %>% 
  filter(id %in% c(2, 4, 5, 6))

# df2: indivíduos 2, 3, 4 e 5 com variáveis id e ocupa
df2 <- surto_modif %>% 
  select(id, ocupa) %>% 
  filter(id %in% c(2, 3, 4, 5))

df1
df2
```

Note que os dois bancos compartilham a coluna `id`, que será usada como chave de ligação. Os indivíduos 2, 4 e 5 aparecem nos dois bancos; o indivíduo 6 aparece apenas em `df1`; e o indivíduo 3, apenas em `df2`.

---

### `left_join()` — todas as linhas da tabela da esquerda

Retorna **todas as linhas de `df1`** e acrescenta as colunas de `df2` quando há correspondência. Linhas de `df1` sem par em `df2` recebem `NA`.

```{r echo=TRUE, eval=TRUE}
df_left <- df1 %>%
  left_join(df2, by = "id")

df_left
```

O indivíduo 6, presente em `df1` mas ausente em `df2`, aparece com `NA` na coluna `ocupa`.

---

### `right_join()` — todas as linhas da tabela da direita

O inverso do `left_join()`: retorna **todas as linhas de `df2`** e acrescenta as colunas de `df1`. Linhas de `df2` sem par em `df1` recebem `NA`.

```{r echo=TRUE, eval=TRUE}
df_right <- df1 %>%
  right_join(df2, by = "id")

df_right
```

O indivíduo 3, presente em `df2` mas ausente em `df1`, aparece com `NA` nas colunas `caso` e `sexo`.

---

### `full_join()` — todas as linhas de ambas as tabelas

Retorna **todas as linhas das duas tabelas**. Onde não há correspondência, preenche com `NA`.

```{r echo=TRUE, eval=TRUE}
df_full <- df1 %>%
  full_join(df2, by = "id")

df_full
```

Todos os indivíduos aparecem. O indivíduo 6 tem `NA` em `ocupa`; o indivíduo 3 tem `NA` em `caso` e `sexo`.

Também é possível usar mais de uma coluna como chave:

```{r echo=TRUE, eval=FALSE}
# Unindo por duas chaves simultaneamente
ex_full <- ex1 %>%
  full_join(ex2, by = c("id", "sexo"))
```

---

### `inner_join()` — apenas linhas com correspondência nos dois bancos

Retorna **somente as linhas que existem nas duas tabelas**. Linhas sem correspondência são descartadas.

```{r echo=TRUE, eval=TRUE}
df_inner <- df1 %>%
  inner_join(df2, by = "id")

df_inner
```

Apenas os indivíduos 2, 4 e 5 — presentes nos dois bancos — são mantidos.

---

### Resumo comparativo

| Função | Linhas mantidas |
|---|---|
| `left_join()` | Todas de `df1`; correspondentes de `df2` |
| `right_join()` | Todas de `df2`; correspondentes de `df1` |
| `full_join()` | Todas de `df1` e `df2` |
| `inner_join()` | Apenas as com correspondência nos dois bancos |

## Exportando dados: `write_csv()` e `write_xlsx()`

Após manipular e transformar o banco de dados, é importante salvar o resultado para uso futuro ou compartilhamento. Para isso, utilizamos funções de exportação.

---

### Exportando para `.csv`

O pacote `readr` oferece as funções `write_csv()` e `write_csv2()` para salvar data frames em formato `.csv`:

```{r echo=TRUE, eval=FALSE}
library(readr)

# Exportando com vírgula como separador (padrão internacional)
write_csv(surto_modif, "surto_modificado.csv")

# Exportando com ponto e vírgula (padrão brasileiro — compatível com Excel em PT-BR)
write_csv2(surto_modif, "surto_modificado.csv")
```

---

### Exportando para `.xlsx`

Para exportar em formato Excel, utilizamos o pacote `writexl`:

```{r echo=TRUE, eval=FALSE}
# Instalar o pacote (apenas uma vez)
install.packages("writexl")

library(writexl)

# Exportando para Excel
write_xlsx(surto_modif, "surto_modificado.xlsx")
```

Para exportar **múltiplas tabelas em abas diferentes** do mesmo arquivo Excel:

```{r echo=TRUE, eval=FALSE}
write_xlsx(
  list("Dados completos" = surto_modif,
       "Sintomas"        = surto2,
       "Resumo"          = surto_modif %>% group_by(caso) %>% summarise(n = n())),
  "surto_relatorio.xlsx"
)
```

---

### Definindo o caminho de saída

Por padrão, os arquivos são salvos no diretório de trabalho atual. Para verificar ou alterar o diretório:

```{r echo=TRUE, eval=FALSE}
# Verificar o diretório atual
getwd()

# Alterar o diretório de trabalho
setwd("C:/Users/seu_usuario/Documents/projeto")

# Ou especificar o caminho completo diretamente na função
write_csv(surto_modif, "C:/Users/seu_usuario/Documents/projeto/surto_modificado.csv")
```
